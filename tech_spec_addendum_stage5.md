## Этап 4: подготовка к продакшену

### 4.1 Хранилище файлов
Сейчас файлы пишутся на локальный диск (`public/uploads`) — на Vercel
файловая система эфемерна, при каждом деплое/рестарте файлы теряются.

Задача: заменить `src/lib/upload.ts` на Supabase Storage (или S3/R2),
сохранив тот же контракт функции (принимает файл, возвращает публичный
URL), чтобы не трогать код, который её вызывает.

### 4.2 База данных
Перевести `prisma/schema.prisma` с `sqlite` на `postgresql`, подключить
`DATABASE_URL` от Supabase, прогнать миграции. Данные из dev-базы можно
не переносить — на проде стартуем с чистой БД + `db:seed` при
необходимости.

### 4.3 Онлайн-оплата тарифов
Сейчас тариф турфирме назначает администратор вручную в
`/admin/companies`. Добавить реальную оплату:
- Для локальных турфирм — любой доступный в КР эквайринг с оплатой по
  QR (уточнить у пользователя, какой провайдер есть на момент
  разработки — интеграции меняются, не полагаться на память)
- Для иностранных клиентов (если появятся) — Stripe
- Логику подписки (дата окончания, автопродление/напоминание) хранить
  в отдельной таблице, не смешивать с самим тарифом

### 4.4 Email-уведомления
- Турфирме — при одобрении/отклонении регистрации
- Турфирме — при новом отзыве
- Использовать любой почтовый сервис с API (Resend, SendGrid и т.п.) —
  выбор оставить на усмотрение исполнителя

### 4.5 Перевод личного кабинета и админки
Расширить существующий `src/lib/i18n/` на `/dashboard/*` и `/admin/*` —
структура словарей уже заложена, нужно добавить недостающие ключи и
обернуть оставшиеся строки.

### 4.6 SEO
Вернуть возможность статической генерации там, где это важно (страницы
турфирм, каталог) — сейчас чтение локали из cookie сделало страницы
динамическими. Рассмотреть query-параметр локали для страниц, которым
нужен ISR/SSG, добавить `sitemap.xml` и `robots.txt`.

## Этап 5: AI-функции

Все пункты используют Anthropic API (Claude) через серверные API routes
Next.js — ключ хранится в `.env`, вызовы идут с бэкенда, не с клиента.

### Приоритет 1 — сделать в первую очередь

**5.1 AI-подбор тура по свободному запросу**
Турист вводит текстом, что хочет ("треккинг на 5 дней, не очень
сложный, ночёвки в юртах"), вместо/вместе с ручными фильтрами.
- API route принимает текст запроса + список доступных туров (или их
  краткие описания) из БД
- Промпт просит Claude вернуть **строго JSON**: список ID подходящих
  туров, отсортированных по релевantности, с коротким объяснением для
  каждого
- Результат подмешивается в выдачу `/search` как альтернатива/дополнение
  к обычным фильтрам

**5.2 Автогенерация описаний для турфирм**
В личном кабинете при создании/редактировании профиля или тура —
кнопка "Сгенерировать описание": турфирма даёт короткие тезисы или
ключевые слова, Claude пишет продающий текст сразу на 3 языках
(рус/кырг/англ). Результат — черновик, который фирма может
отредактировать перед публикацией (не публиковать автоматически).

**5.3 Автоперевод отзывов и описаний**
На странице турфирмы у отзывов и у описания — кнопка/переключатель
"Показать перевод". Вызов Claude API с переводом на язык интерфейса,
выбранный туристом. Кэшировать перевод в БД (отдельное поле или
таблица `Translation`), чтобы не переводить один и тот же текст
повторно при каждом просмотре.

### Приоритет 2 — по желанию, после приоритета 1

**5.4 AI-чат-помощник**
Виджет на сайте отвечает на общие вопросы туристов (сезонность, виза,
транспорт) на основе контента платформы. Ограничить контекст только
данными сайта, чтобы не давать недостоверные советы от общего знания
модели без проверки.

**5.5 Summary длинных PDF-гидов**
При загрузке PDF-гида турфирмой — фоновая генерация короткого summary
(3–4 предложения) для показа на карточке тура, сам PDF остаётся
доступен для скачивания целиком.

**5.6 Анализ отзывов для админа/турфирмы**
Периодическая (или по запросу) сводка по отзывам конкретной турфирмы:
что хвалят, на что жалуются. Показывать в `/dashboard/stats` и как
вспомогательный инструмент в `/admin`.

**5.7 Детекция подозрительной активности**
Простая эвристика + при необходимости Claude API для оценки текста
отзыва на признаки накрутки/спама (много похожих отзывов за короткое
время, шаблонный текст) — флаг для ручной проверки админом, не
автоматическое удаление.

### Не включать в MVP+ без отдельного обсуждения
**5.8 Предиктивная аналитика спроса** (подсказки по ценам/акциям на
основе сезонности) — требует накопленных данных за продолжительный
период, преждевременно для платформы без истории; вернуться к этому
после нескольких месяцев реальной эксплуатации.

## Технические заметки для реализации AI-функций

- Все промпты, где нужен структурированный ответ (5.1), явно требовать
  "ответь только JSON, без пояснений и markdown" и парсить с
  try/catch на случай отклонений от формата
- Не хранить API-ключ Anthropic на клиенте — только в серверных
  переменных окружения, вызовы — из API routes
- Для 5.3 (переводы) — кэшировать результат, иначе расходы на API
  будут расти линейно с просмотрами, а не с объёмом уникального
  контента
- Черновики от AI (5.2) всегда показывать пользователю на
  подтверждение перед сохранением — не публиковать автоматически
  сгенерированный текст без просмотра человеком
