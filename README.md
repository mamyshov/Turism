# KyrgyzTour Hub

MVP-платформа для турфирм и частных гидов Кыргызстана. Туристы находят
компании через каталог с фильтрами, смотрят фото и туры и связываются
напрямую; турфирмы регистрируются, проходят модерацию и ведут профиль из
личного кабинета.

Реализовано согласно **Этапам 1, 2, 3** технического задания
(`tech_spec_tourism_platform.md`) и пункту **5.1 Этапа 5**
(`tech_spec_addendum_stage5.md`) — AI-подбор тура. Сверх ТЗ добавлена
лёгкая «соцсетевая» фича — публичная лента коротких видео `/reels`
(см. ниже).

## Стек

- **Next.js 14** (App Router) + TypeScript + Tailwind CSS
- **Prisma** + **SQLite** для локальной разработки без внешних сервисов.
  Схема написана с расчётом на Postgres — для продакшена достаточно
  поменять `provider` в `prisma/schema.prisma` на `postgresql` и указать
  `DATABASE_URL` (например, от Supabase).
- **NextAuth.js** (Credentials provider, JWT-сессии) — упрощённый аналог
  Supabase Auth, чтобы MVP не зависел от внешнего аккаунта на старте.
- Загрузка файлов — на локальный диск (`public/uploads`) через встроенный
  `FormData` API. Для продакшена замените `src/lib/upload.ts` на
  Supabase Storage / S3 / R2 — остальной код зависит только от того, что
  функция возвращает публичный URL.
- **Мультиязычность** — собственное лёгкое решение на cookie
  (`src/lib/i18n/`), а не next-intl: без смены URL (`/search` остаётся
  `/search` на любом языке), без риска ломающего рефакторинга всех
  страниц под `[locale]`. Подробности и границы охвата — ниже.
- **Anthropic API (Claude)** — для AI-подбора тура (`@anthropic-ai/sdk`),
  вызывается только с сервера (API route), ключ не покидает бэкенд.

## Что реализовано

**Этап 1:**
1. Инициализация проекта (Next.js + Tailwind + Prisma)
2. Регистрация турфирм/гидов (юрлицо или частный гид, загрузка документа
   для верификации) и логин
3. Личный кабинет: редактирование профиля (описание, регион, языки,
   категории туров, контакты) + загрузка фото (лимит зависит от тарифа)
4. Публичный каталог с фильтрами (регион, тип тура, язык, цена, поиск по
   тексту)
5. Страница турфирмы: галерея фото, туры, контакты (WhatsApp/звонок/email)

**Этап 2:**
6. Видео-гиды (ссылка на YouTube/Vimeo с авто-конвертацией в embed, либо
   загрузка файла MP4/WEBM/MOV) и PDF-гиды в личном кабинете — доступны
   с тарифа «Стандарт», на «Базовом» показывается предложение сменить
   тариф
7. Отзывы и рейтинг: любой турист может оставить отзыв (имя, email,
   оценка 1–5, текст) на странице турфирмы без регистрации; средний
   рейтинг и число отзывов показываются на карточке и странице компании
8. Панель администратора: модерация новых турфирм (одобрить/отклонить с
   комментарием), список всех турфирм с блокировкой/удалением, модерация
   отзывов (удаление спама)

**Этап 3:**
9. Тарифы и биллинг: администратор меняет тариф турфирмы прямо в списке
   `/admin/companies` (без реальной оплаты, как и предполагает ТЗ на
   старте)
10. Статистика просмотров: график за последние 30 дней (`DailyView`
    в БД) плюс общий счётчик, на странице `/dashboard/stats`
11. Мультиязычность: переключатель Рус/Кырг/Англ в шапке сайта.
    **Переведён весь туристический интерфейс** — главная, каталог с
    фильтрами, страница турфирмы (включая отзывы), вход/регистрация,
    о проекте, контакты, названия регионов/категорий/языков. Личный
    кабинет турфирмы и панель администратора остаются на русском —
    ими пользуются владельцы бизнеса и модераторы, а не туристы, поэтому
    их перевод сознательно вынесен за рамки этого MVP.

**Этап 5 (AI, пункт 5.1):**
12. **AI-подбор тура** — блок «🤖 AI-подбор тура» вверху `/search`.
    Турист описывает запрос свободным текстом ("треккинг на 5 дней, не
    очень сложный, ночёвки в юртах"), сервер (`/api/ai/tour-search`)
    отправляет запрос и список доступных туров в Claude (`claude-opus-5`,
    структурированный вывод через Zod-схему — `client.messages.parse` +
    `zodOutputFormat`, без хрупкого ручного парсинга JSON из текста) и
    возвращает отсортированный по релевантности список с коротким
    объяснением для каждого тура на языке интерфейса. Результаты ведут на
    страницу турфирмы с якорем на конкретный тур. Работает как дополнение
    к обычным фильтрам, не заменяя их.
    - Требует `ANTHROPIC_API_KEY` в `.env`; без ключа блок на `/search`
      сразу показывает «AI-подбор временно недоступен» — сборка,
      остальной функционал и типы не зависят от наличия ключа.
    - Каталог туров целиком передаётся в промпт — рабочий вариант для
      MVP-масштаба (десятки–сотни туров). При росте каталога до тысяч
      записей нужен этап предфильтрации (по региону/категории или
      полноценный retrieval/embeddings) перед этим лимитом — см.
      комментарий `MAX_TOURS_IN_PROMPT` в
      `src/app/api/ai/tour-search/route.ts`.
    - ID туров, вернувшиеся от модели, дополнительно валидируются против
      реальной БД перед показом — «придуманный» ID молча отфильтровывается.

**Сверх ТЗ — «половина соцсети»:**
13. **Лента коротких видео (`/reels`)** — публичная вертикальная лента в
    стиле TikTok/Reels: свайп/скролл на весь экран, автовоспроизведение
    только видимого ролика (через `IntersectionObserver`, чтобы не грузить
    процессор десятками параллельных видео), тап по видео — вкл/выкл звук,
    лайк (❤️), переход в профиль турфирмы.
    - Загружать ролики может **любая турфирма** из личного кабинета
      (`/dashboard/reels`) — независимо от тарифа: это фича роста для всей
      платформы, а не платный бонус, в отличие от «Видео-гидов» из Этапа 2.
      До 20 роликов на компанию, MP4/WEBM/MOV, до 50 МБ.
    - Лайки анонимные — без полноценных аккаунтов туристов (которых в
      продукте по-прежнему нет) через одноразовый `httpOnly`-cookie с
      случайным ID посетителя (`src/lib/visitor.ts`), с уникальным
      ограничением `(reelId, visitorId)` в БД — простое, но настоящее
      ограничение от накрутки повторными кликами, не просто счётчик на
      клиенте.
    - Осознанно **не делали**: аккаунты туристов, комментарии, подписки —
      это увело бы проект в полноценную соцсеть. Взяли только то, что
      создаёт эффект вовлечения при минимальном объёме кода.

Дополнительно, чтобы цикл был рабочим целиком:

- Управление турами в личном кабинете (CRUD)
- Заблокированная администратором турфирма скрывается из каталога и
  публичной страницы (404), но видит статус в своём личном кабинете

## Локальный запуск

```bash
npm install
cp .env.example .env      # уже создан, значения по умолчанию подходят для dev
npm run db:push           # создаёт SQLite базу по schema.prisma
npm run db:seed           # админ + 3 демо-турфирмы
npm run dev
```

Откройте http://localhost:3000.

Чтобы включить AI-подбор тура (необязательно для остального функционала),
впишите свой ключ в `.env`:

```bash
ANTHROPIC_API_KEY="sk-ant-..."
```

**Демо-доступы после `db:seed`:**
- Админ: `admin@kyrgyztourhub.kg` / `admin12345` → `/admin/moderation`
- Турфирма (уже одобрена): `issykkul-trek@example.com` / `demo12345` → `/dashboard/profile`

Чтобы проверить полный цикл регистрации: зарегистрируйте новую турфирму на
`/register` — она попадёт в `/admin/moderation` со статусом «На
модерации»; после одобрения администратором профиль появится в `/search`.

## Структура

```
prisma/schema.prisma       модель данных (см. комментарии в файле)
prisma/seed.ts             демо-данные
src/app/                   страницы (App Router) и API routes
src/app/api/ai/            AI-функции поверх Anthropic API
src/components/            переиспользуемые UI-компоненты
src/lib/                   auth, prisma client, константы, загрузка файлов
src/lib/i18n/              словари переводов, локаль из cookie
src/lib/anthropic.ts       клиент Anthropic API (только серверный код)
```
